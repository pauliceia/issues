# Pauliceia 2.0 — Issues & Contribution Hub

This repository serves as the central hub for project governance, cross-repository issues, documentation, and contribution standards for the **[Pauliceia 2.0](https://github.com/pauliceia)** organization.

---

## 🤝 Contributing to Pauliceia 2.0

All repositories under the Pauliceia 2.0 organization share a **single centralized contribution guide**:

👉 **[Read the Official Contributing Guide (`CONTRIBUTING.md`)](CONTRIBUTING.md)**

Inside `CONTRIBUTING.md`, you will find:

- **Issue naming conventions** (`[FEATURE]`, `[FIX]`, `[BUG]`, `[DOCS]`, `[REFACTOR]`, `[CHORE]`)
- **Branch naming standards** (`type/issue-number-short-description` from `master`)
- **Pull Request & Commit standards** ([Conventional Commits](https://www.conventionalcommits.org/) + `Closes #<issue>`)
- **Complete workflow lifecycle** (`Issue` → `Branch` → `PR` → `Review` → `Merge into master` → `Project → Done`)
- **Repository setup & contribution steps**

> Each individual repository's `README.md` links directly to this guide.

## 📝 Opening Issues on GitHub (Quick Guide)

To create and track tasks transparently across the **Issues** and **Projects** tabs:

1. Go to the **Issues** tab in the target repository and click **New issue**.
2. Choose the appropriate template (when available under `.github/ISSUE_TEMPLATE/`) and follow the `[CATEGORY] Short description` title convention described in [`CONTRIBUTING.md`](CONTRIBUTING.md).
3. Use the right-hand sidebar on GitHub to configure:
   - **Assignees:** Assign the person(s) responsible for the task.
   - **Labels:** Categorize the issue (`bug`, `documentation`, `enhancement`, etc.) to make filtering easier.
   - **Projects:** Link the issue to the project board so its status (`To do`, `In progress`, `Done`) stays synchronized automatically.
   - **Milestones:** Associate the issue with a target deadline or sprint milestone, when applicable.
4. Click **Submit new issue**.
